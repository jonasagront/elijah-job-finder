# Elijah's Job Finder

Every 6 hours this repo scans tech company career sites and big new-grad job lists for
**entry-level software, AI/ML, and data jobs** (plus internships that a recent grad can take),
scores each one against Elijah's resume, and publishes the results to a page he can open on his phone.

**Job page:** `https://<your-github-username>.github.io/<repo-name>/` (turn it on in step 2 below)

## One-time setup (about 10 minutes)

### 1. Put the files on GitHub
**With GitHub Desktop (easiest):**
1. **File → Add local repository**, choose this `elijah-job-finder` folder. If it asks, click
   **create a repository** here, then **Create repository**.
2. Click **Publish repository**. **Uncheck "Keep this code private"** (GitHub Pages is free only
   for public repos), then **Publish**.

**Or in the browser:**
1. Create a new empty repository on github.com (public).
2. Click **uploading an existing file**, drag in **everything inside this folder**, and commit.
   The `.github` folder is hidden on a Mac (press **Cmd + Shift + .** in Finder to show it).
   Make sure the repo shows `.github/workflows/daily.yml` afterwards.

### 2. Turn on the job page
1. In the repo, go to **Settings → Pages**.
2. Under **Build and deployment**, set **Source** to **Deploy from a branch**.
3. Set the branch to **main** and the folder to **/docs**, then click **Save**.

### 3. Run the first scan
1. Go to the **Actions** tab. If GitHub asks, click **I understand my workflows, go ahead and enable them**.
2. Click **Daily job scan** on the left, then **Run workflow → Run workflow**.
3. Wait about 5 to 10 minutes for a green check mark. The page updates a minute or two after that.

From then on it runs by itself every 6 hours.

## How the score works (out of 100)

- **Role fit, up to 40.** Software / AI / data words in the title and description (developer,
  Python, machine learning, backend...), majors listed (Computer Science earns the most), and
  whether it's a known tech employer.
- **Skills, up to 35.** How many of Elijah's resume skills the posting asks for (Python, React,
  TypeScript, Rust, SQL, cryptography...), weighted by how strong each one is. Close substitutes
  (Vue instead of React, C++ instead of Rust) get half credit.
- **Eligibility, up to 25.** Points come off when a posting asks for 1+ years of experience, when
  an internship only takes current students, for graduation windows that don't include Dec 2025,
  and for master's/PhD-only roles. Postings that want more than 4 years are hidden entirely.

Fit labels: **Strong fit** 72+, **Good fit** 56 to 71, **Worth a look** 40 to 55.
Anything below 40 is hidden.

Tags like **Florida**, **Remote**, **U.S. person**, and **Clearance** are shown so he can filter
quickly; they don't change the score. The page's **Florida or remote** switch shows only those.

## Tuning it

- **`profile.toml`**: skills, which titles count as entry level, titles to skip, home locations,
  the minimum score. Add a skill when he learns one (Git, AWS, Docker...) and future scores pick it up.
  The "Skills to learn next" box on the page shows which missing skills come up most.
- **`sources.toml`**: which companies and lists get checked. The bottom of the job page
  shows which sources worked on the last run, so it's clear what to fix or remove.

**Note:** GitHub pauses scheduled runs in repos with no activity for 60 days. If that ever
happens, GitHub sends an email; open the Actions tab and re-enable the workflow.
